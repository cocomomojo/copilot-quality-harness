# Issue #56 パース問題：最終レポート

## 📋 問題概要

GitHub Actions ワークフロー（m2-issue-intake.yml）が Issue #56 を検証する際に、以下の情報が「不足」と判定されていた：

```
missing information: acceptance criteria, test requirements, severity
```

実際には本文内に全て記載されていたため、**パーサーの不具合** が原因。

---

## 🔍 根本原因分析

### Issue #1: 受入条件・テスト要求が検出されない

**原因：** 正規表現パターンの行末処理

```javascript
// 問題のあるパターン
const pattern = new RegExp(`^##\\s+${escaped}[^\\n]*$([\\s\\S]*?)(?:^##|$)`, 'im');
```

- `$` で行末にマッチ
- その直後のキャプチャグループ `([\\s\\S]*?)` が開始されるが、次の `(?:^##|$)` が直後の改行に即座にマッチ
- **セクション本文がキャプチャされない** → Empty array

### Issue #2: 重大度が検出されない

**原因：** テキストのクリーニング不足

```
セクション内容: "\nlow\n\n---\n"
→ SEVERITIES.has() が false
```

ホワイトスペース・改行・区切り線が含まれたまま判定 → 不一致

### Issue #3: セキュリティキーワードで不正に停止

**原因：** キーワード検出の過度な単純さ

「認証を含まない軽微なUI改善」でも「認証」キーワード検出 → 停止

---

## ✅ 実施した修正

### 修正 #1: 正規表現パターンを改善

```javascript
// 修正後
const pattern = new RegExp(`^##\\s+${escaped}[^\\n]*\\n([\\s\\S]*?)(?=^##|\\Z)`, 'im');
```

**変更点：**
- `$` から `\n` に（改行を明示的に含める）
- `(?:^##|$)` から `(?=^##|\Z)` に（先読みで正確に次の見出しまで）
- 区切り線 `---` をフィルタリング

### 修正 #2: 重大度テキストをクリーニング

```javascript
const severityRaw = section(...).toLowerCase().trim();
const severityText = severityRaw.split(/[\s\n-]+/)[0]; // 最初の単語のみ抽出
```

### 修正 #3: 禁止キーワード検出に否定表現フィルタリング

```javascript
const hasNegation = /(?:影響なし|含まない|変更なし|...)/i.test(securitySection);
if (!hasNegation && /(?:認証|個人情報|...)/i.test(section)) {
  policyStops.push('restricted scope');
}
```

### 現在のアプローチの限界

| 問題 | 原因 |
|-----|------|
| マークダウンバリエーション非対応 | 正規表現は固定パターンのみ |
